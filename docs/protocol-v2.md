# Второй эксперимент

Протокол закрепляется до проверки S2 и S3. S1 уже обсуждался и считается разработочной записью. Его старый тест больше не служит независимым доказательством улучшения.

На S1 используются только повторы 1, 3, 4 для обучения и 2 для выбора конфигурации. Сравниваются окна 50, 75, 100, 150 мс; исходные 40 временных признаков и их логарифмы; LDA с shrinkage=auto и SVM RBF с C=1 или C=10. Всего 24 конфигурации. Для каждой модели выбирается максимум macro-F1 на валидации; при равенстве — меньшее окно. Большое окно допускается в сравнении, но не доказывает выполнение 100 мс.

Калибровка — sigmoid, GroupKFold(3) по обучающим повторам, ensemble=False. В отличие от первой версии итоговый классификатор обучается на всех трёх повторах. Параметры масштабирования оцениваются отдельно внутри каждого обучающего fold. Калибровка может менять порядок классов; сравниваются именно откалиброванные ответы.

После сохранения frozen_config.json процедура проверяется на S2 и S3. Это два заранее выбранных следующих номера, а не лучшие записи. Для каждого нового человека модель персональная: train [1,3,4], validation [2], test [5,6]. Веса обучаются заново на его train. Таким образом проверяется повторяемость процедуры на новых людях после настройки, а не перенос готовой модели между людьми или днями.

Проверка команды на персональной валидации: порог {0; 0,5; 0,65; 0,8; 0,9}, разница двух лучших оценок {0; 0,15; 0,3}, подтверждения {1; 2; 3}. Из режимов с принятием не менее 70% окон выбирается минимальная доля ошибок среди принятых; при равенстве — больше ответов за 100 мс, затем больше принятых окон. Если ни один режим не удовлетворяет ограничению, это явно отмечается. Режим без проверки сохраняется как сравнение, а не разрешение работы привода.

Исследовательские ориентиры: ошибки среди принятых <=10%, принятие >=70%, первая правильная команда за 100 мс хотя бы для 90% движений. Эти числа выбраны для оценки прототипа, не являются медицинской нормой и не заменяют требование ТЗ о полной задержке <=100 мс. Ни один программный результат не подтверждает задержку реального привода.

Основные метрики: raw accuracy, macro-F1, покрытие, ошибки среди принятых, ошибочные переключения в минуту, медиана/p95 первой правильной команды, доля всех движений с ответом за 100 мс и число пропусков. Дополнительно — момент завершения первых 100 мс непрерывных правильных команд и число движений без такого участка. Это защищает от трактовки случайного правильного кадра как устойчивого управления. Такая метрика по определению включает 100 мс наблюдения, поэтому не подменяет исходную задержку.

Пропуск команды кодируется -1; покой — 0. Любой отказ должен запрещать движение. Переходные окна сохраняются в тесте. Разброс между двумя людьми показывается отдельно; узкие доверительные интервалы по зависимым окнам не рассчитываются.

После просмотра S2/S3 настройки этой версии не меняются. При необходимости следующая гипотеза требует новых отложенных данных. Первые результаты остаются в results/db2_s1; новые — в results/study. Исходные записи не публикуются в репозитории.

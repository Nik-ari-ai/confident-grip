# Уверенный хват

Студенческий проект для кейса СТЕПЛАЙФ на SK Challenge 2026.
По восьми каналам поверхностной ЭМГ программа распознаёт пять хватов и покой.
Перед выдачей команды проверяются качество сигнала, оценка модели и подтверждение.

Сейчас это программный прототип на записях NinaPro DB2. Настройки выбраны на S1,
затем процедура проверена на S2 и S3 с персональным обучением. Кисть не подключена.
Полная задержка 100 мс не подтверждена; ошибок пока слишком много для управления приводом.

[Отчёт, 9 страниц](docs/report.pdf) · [Текст отчёта](docs/report.md) ·
[Презентация, 7 слайдов](docs/presentation.pptx) · [Что проверять при ревью](docs/review.md)

Для демонстрации скачайте репозиторий и откройте `docs/demo.html` обычным браузером.
Файл работает без сервера и интернета. Можно выбирать записи, двигать ползунок
и воспроизводить команды. Это просмотр результатов, не модель в браузере.

## Что изменилось после первого опыта

Сравнены 24 конфигурации окна, признаков и классификатора. При калибровке итоговая
модель теперь обучается на всех трёх train-повторах. У SVM выбран логарифм
амплитудных признаков, окно 100 мс, C=10; у LDA — исходные признаки и окно 150 мс.

Порог, разница двух лучших оценок и число подтверждений выбираются при принятии
не менее 70% окон на валидации. Это устраняет выигрыш за счёт почти полного отказа.
Ограничение не гарантируется на новых данных: на тесте S3 принято 67,8%.

| Новый участник | Модель | Точность до проверки | Macro-F1 | Принято | Ошибки среди принятых |
|---|---|---:|---:|---:|---:|
| S2 | LDA | 57,4% | 0,534 | 86,8% | 38,0% |
| S2 | SVM | 65,2% | 0,602 | 86,5% | 29,3% |
| S3 | LDA | 47,7% | 0,451 | 84,8% | 48,7% |
| S3 | SVM | 57,7% | 0,541 | 67,8% | 32,0% |

На одинаковых временных точках точность SVM выросла с 61,7 до 65,2% на S2
и с 52,0 до 57,7% на S3 относительно первой версии. Сравнение находится в
`results/study/paired_comparison.json`. Вклад каждой правки отдельно не установлен.

У новой SVM проверка уменьшила ошибочные переключения в минуту с 482 до 178
на S2 и с 546 до 175 на S3. Но снижение числа переключений не означает
достаточной надёжности: около трети принятых команд неверны. Особенно слабое
место — покой. Следующий опыт должен проверить детектор активности и более
короткое окно на новых данных. Тесты S2/S3 нельзя снова использовать для подбора.

## Протокол

S1 — разработочная запись. Выбор конфигураций: train [1,3,4], validation [2].
Его ранее просмотренный тест не используется как независимое подтверждение.
[Протокол](docs/protocol-v2.md) и `frozen_config.json` закреплены коммитом
`fe22ce7` до расчёта тестов S2/S3.

На каждом новом участнике: train [1,3,4], validation [2], test [5,6].
Модель и пороги персональные. Это проверка процедуры настройки на новых людях,
а не перенос одной модели между людьми или днями. Все участники без ампутации.
Калибровка — sigmoid, GroupKFold(3) по train-повторам, ensemble=False.
Масштабирование обучается отдельно внутри каждого fold. Тестовые переходы сохранены.

Из DB2 выбраны метки 19, 32, 34, 20, 27 и покой. На человека: 30 фрагментов,
из них 10 тестовых. Берутся первые восемь каналов и до 0,5 с соседнего покоя.
Неиспользуемые движения не склеиваются. Тысячи перекрывающихся окон не являются
независимыми людьми или испытаниями.

## Запуск

Проверено на Python 3.12. Требуется Python 3.10 или новее.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -m pip install --no-deps -e .
python -m unittest discover -s tests -v
```

Скачивание трёх архивов занимает около 1,4 ГБ, распакованные записи — ещё около
0,7 ГБ. Данные не входят в репозиторий. Описание и условия:
[NinaPro DB2](https://ninapro.hevs.ch/instructions/DB2.html).

```sh
python scripts/download_db2.py --subject 1
python scripts/download_db2.py --subject 2
python scripts/download_db2.py --subject 3
```

Повторить подбор на S1 и проверку новой версии:

```sh
python -m confident_grip.study tune --data data/S1_E2_A1.mat --output results/local/development
python -m confident_grip.study test --data data/S2_E2_A1.mat --config results/local/development/frozen_config.json --output results/local/s2
python -m confident_grip.study test --data data/S3_E2_A1.mat --config results/local/development/frozen_config.json --output results/local/s3
```

Чтобы воспроизвести только тест, можно передать сохранённый
`results/study/development/frozen_config.json`. Контрольные суммы исходных
MAT-файлов и конфигурации записаны в `metrics.json`.

Первый вариант и искусственный пример сохранены отдельно:

```sh
grip-experiment --data data/S1_E2_A1.mat --output results/local/original_s1
grip-experiment --data data/S2_E2_A1.mat --output results/local/original_s2
grip-experiment --data data/S3_E2_A1.mat --output results/local/original_s3
grip-experiment --output results/local/synthetic
```

В `results/db2_s1` и `results/synthetic` лежат исторические результаты.
В `results/study/original_s2` и `original_s3` — первая процедура на новых записях
для сравнения. Собственные прогоны сохраняйте отдельно, чтобы не перезаписывать
результаты проекта. Время вычислений зависит от компьютера и фоновых процессов.

## Как читать задержку

Первая правильная команда считается от метки `restimulus` до конца доступного
окна. Ноль означает, что команда уже была правильной на границе метки;
это не мгновенная физическая реакция. Пропуски показаны отдельно, а в доле
движений с ответом за 100 мс они остаются в знаменателе.

Дополнительная метрика фиксирует конец первых 100 мс непрерывно правильных
команд. Медиана SVM — 375 мс на S2 и 980 мс на S3. Она включает 100 мс
наблюдения и не заменяет первую задержку. Так видно отличие случайного
правильного кадра от устойчивого ответа.

Одна вычислительная итерация SVM занимает примерно 1,2–1,3 мс (p95, компьютер),
но физический съём, фазовая задержка тракта, связь и механика не измерены.
Окно 100 мс не гарантирует отклик за 100 мс. В отчёте приведён отдельный
проектный бюджет следующей короткооконной версии, а не достигнутый результат.

## Файлы и проверки

- `data.py`: DB2 и отдельный искусственный пример для отладки.
- `processing.py`: причинный фильтр, признаки, проверка сигнала.
- `control.py`: выдача команды или запрета.
- `experiment.py`: исходный опыт, общие метрики и замер вычислений.
- `study.py`: подбор на S1, закреплённая процедура на S2/S3.
- `tests`: 20 проверок причинности, разделения, отказов, margin,
  ограничения покрытия и метрик задержки.
- `scripts/build_summary.py`: сравнение версий на совпадающих точках.
- `scripts/build_demo.py`: сборка автономного просмотра сохранённых CSV.
- `scripts/build_presentation.mjs`: исходник слайдов для среды с `@oai/artifact-tool`;
  готовый PPTX редактируется обычным PowerPoint.
- `scripts/build_report.py`: сборка PDF и текста отчёта; нужен reportlab,
  `--font` и `--bold-font` с путями к кириллическим TTF.

В каждом новом `metrics.json`: конфигурация, все варианты настройки на валидации,
четыре режима теста, матрица ошибок, полнота классов и время вычислений.
CSV содержит каждое решение; картинки показывают первый фрагмент без отбора удачных.

## Привод и ограничения

`inhibit=True` должен явно останавливать движение. Просто прекратить отправку
недостаточно: может продолжаться прежнее сжатие. Покой не означает раскрытие.
Удержание усилия и раскрытие задаются отдельно для механики. На приводе нужен
независимый таймер отсутствия свежих команд: при полном отсутствии пакетов
Python-функция сама не вызовется. Уверенные устойчивые ошибки проверка не устраняет.

Бюджет стенда 160 000 руб. — распределение лимитов, не предложения поставщиков.
Срок 3–6 месяцев предполагает лабораторию; клинические испытания и зарплата
не входят в смету. Текст защиты и ответы на вопросы — в [defense.md](docs/defense.md).
